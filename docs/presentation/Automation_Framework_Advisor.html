⭐ Headline integration

Already works inside Kiro — zero extra infrastructure

This isn't a roadmap item. The advisor ships its own MCP (Model Context Protocol) server today, exposing all 20 tools directly to Kiro's chat. Any engineer can call it from any repo they have open, right now.

🔧 One-time setup — one command

# Registers the server for every Kiro workspace
python scripts/setup_mcp.py --user

# That's it — reconnect from Kiro's MCP Server view
# and all 20 tools become available in chat.

📄 Or point mcp.json at it directly

{
  "mcpServers": {
    "automation-framework-advisor": {
      "command": "<python-with-deps>",
      "args": ["<repo>/mcp_server/server.py"],
      "cwd": "<repo>",
      "disabled": false
    }
  }
}

Why migrations fail (and how this prevents it)

Every known migration failure mode has a specific, automated check

✓

Dropped assertions — every conversion runs an assertion-count comparison between source and converted code before it's considered done.

✓

Code that "looks right" but doesn't compile — real compiler/parser checks (ast.parse, robot.api, node --check) catch syntax issues immediately, with auto-repair retries.

✓

Inconsistent LLM output — a dedicated consistency-check tool runs the same conversion N times and reports a reproducibility score before you trust it at scale.

✓

Orphaned test logic — structural checks ensure every converted helper/keyword is actually called by a runnable test case, not left dangling.

✓

"We think we migrated everything" — the Repo Comparator gives a definitive, file-by-file parity report across the whole repo, not a spot check.

✓

Choosing the wrong framework in the first place — the weighted scoring matrix is tailored to the project's real architecture, team language, and CI/CD setup.
